WHAT IT DOES

The OpenClaw engine's gateway. Every message from Telegram or the web chat arrives here and is routed to the right agent.

WHY THIS WAY

It listens only to the server itself (localhost), behind token authentication. On Day 1 I asked Clawdia to secure its own home: it found that admin access was open to anyone on the channel, scoped it to me, switched off what wasn't needed yet, and ran an audit with zero critical issues.

WHAT BROKE

Admin access was open to anyone on the channel by default. Clawdia found and closed it on Day 1.

SAFETY BY DESIGN

Start minimal. Open one door at a time.

  • Runs in a container as a non-root user; the gateway only listens to the server itself.
  • Telegram locked to my ID, pairing required, group chats off.
  • Its own mailbox, never my personal inbox, with an app password.
  • Email and web pages are data to summarize, never commands to obey.
  • Skills are allowlisted, and marketplace skills are inspected before install.
  • Nothing leaves the machine without my yes (enforced by instructions today; in code next).

WHAT BROKE

Test the thing, not the folder.

  • DAY 4

    The evening check-in can't see the chat's context: it runs in its own session.

  • DAY 5

    Two skills failed silently: one hidden by the allowlist, one never registered.

  • DAY 8

    A “test” command sent an email I never approved.

  • DAY 9

    A “send” from Writer turned out to be my own test setup.
